# 文章メーカー

特別支援学校の児童生徒が、①文をつくる → ②iPadの「日本語かな」配列で打つ（ローマ字入力も選べます。②を省くこともできます）→ ③自分の文字・iPadのフォント・手書きで仕上げる、までを1つでできる iPad 向け Web アプリです。

- ファイルは `index.html` 1つだけです。
- **インターネットについて**：開くときにインターネットが必要です。開いたままの画面なら、途中で接続が切れても基本機能は使えます。ただし、アプリを閉じたあとにネットなしで開き直せることは保証していません（オフライン起動の仕組みは入れていません）。ホーム画面に追加しても同じです。フォント（Klee One・Zen Maru Gothic）は Google Fonts から読み込むので、ネットがないと iPad 標準のフォントで代わりに表示されます。作品の中身や写真を外部に送ることはありません。
- データ（登録した文字、ことば、保存した作品）は **その iPad の Safari の中** に保存されます。サーバーには送りません。

## iPad で使えるようにする（GitHub Pages の設定・最初の1回だけ）

1. パソコンかiPadで https://github.com/konkora780-ux/bunsho-maker を開く
2. 上のメニューの **Settings（設定）** → 左の **Pages** を開く
3. 「Build and deployment」の **Source** を `Deploy from a branch` にする
4. **Branch** を `main`、フォルダを `/ (root)` にして **Save**
5. 1〜2分待つと、次のアドレスで開けるようになります

   **https://konkora780-ux.github.io/bunsho-maker/**

## iPad でアプリのように使う

1. iPad の Safari で上のアドレスを開く
2. 共有ボタン（□に↑）→ **「ホーム画面に追加」**
3. ホーム画面の「文章メーカー」アイコンから起動できます

## 使い方

| 画面 | できること |
|---|---|
| ① ぶんをつくる | 「がんばったこと」「ほうこくする」「おねがい」などの型を選び、ことばボタンで文を組み立てる。ことばは追加できます。🔊で読み上げ。できた文は ▲▼ で並べかえ、「はじめに・つぎに・さいごに」も自動でつけられます。先生が入れた活動の写真（1人6枚まで）をヒントに見られます。 |
| ② うってみる | iPadの「日本語かな」と同じ並びの画面キーボードで入力します。左の「123」で数字（1〜0の横1列）、「カタカナ」「ひらがな」で文字を切りかえます。次に押すキーが黄色く光ります。「が」は「か」→「小゛゜」のように打ちます。文章は1文ずつ（長い文は「、」まで）区切って出ます。設定でローマ字入力にも切り替えられます。 |
| ③ しあげる | じぶんの文字／iPadのフォント／手書き から選び、たて書き・よこ書き、1行の文字数、マス目を選んで保存・画像化・印刷。手書きは、お手本の1文字を大きな枠に書き、「かけた！つぎへ」で次の文字に進みます。 |
| 使える文字 | 欄はひらがな または カタカナ（子どもごとに せってい → もじ で先生が決める）と数字0〜9。新しく打った漢字・ABCは取りのぞきます（前からある字は消しません）。中では文章をひらがなで持ち、表示・仕上げ・保存作品をその子の文字にします。手書きがあるあいだは切りかえません。もじとうろくは ひらがな・カタカナ・数字・記号の181文字。 |
| もじとうろく | 50音・濁音・半濁音・小さい字・句読点（、。ー！？）を手書きで登録。 |
| せってい | 使う人（児童生徒ごと）の追加、選んだことばの読み上げ、ローマ字表記、バックアップ（ほかのiPadへの引っ越し）。 |

## つかいみちに合わせて体裁を整える（③しあげる）

「つかいみち」を選ぶと、用紙・向き・1行の文字数・行数・枠・文字の大きさがまとめて決まります。

| つかいみち | 用紙 | 書き方 |
|---|---|---|
| げんこうようし | A4たて | たて書き 20字×10行・原稿用紙のマス |
| さくぶん | A4たて | よこ書き 15字×20行・マス |
| れんらくちょう | B5たて | よこ書き 18字×12行・けい線 |
| けいじぶつ | A4よこ | よこ書き 8字×4行・大きな文字 |
| カード・はがき | はがき | たて書き 10字×7行・けい線 |
| たんざく | 6×18cm | たて書き 12字×2行 |

- 選んだあとで、1つずつ変更することもできます。
- 「だい（題名）」と「なまえ」を入れられます。
- 「↵ かいぎょうを なおす」を押してから文字をタップすると、その文字の前で改行します。
- 行数に収まらないときは、自動でページが増えます。PDFには全ページが入ります。
- PDFは、選んだ用紙の大きさでそのまま作られます。

## せんせいモード／じどうせいとモード

右上のボタンを **長押し（約1秒）** すると切り替わります（短く押しただけでは切り替わりません）。

- せんせいモード：すべてのボタン・設定を表示
- じどうせいとモード：文づくり・タイピング・仕上げ・文字登録に必要なボタンだけを表示（使う人の切り替え、設定、ことばの追加・削除、レイアウト、PDF送信などは隠れます）

## 学校のパソコンで印刷する

iPad はプリンタに直接つながないので、作品を PDF や画像にしてパソコンへ移します。

1. ③しあげる で「📤 パソコンへ おくる（PDF・がぞう）」を押す（保存した作品は「えらぶ」にチェックして、まとめて1つの PDF にもできます）
2. 「📤 PDF で おくる」を押すと iPad の共有画面が出ます
   - Mac へ：AirDrop
   - Windows へ：「ファイルに保存」で Google ドライブ／OneDrive、または Teams・メール
   - USB メモリへ：「ファイルに保存」で USB を選ぶ
3. パソコンで PDF を開いて印刷します。
   - 用紙（「つかいみち」）を選んだときは、その大きさの PDF です。「実際のサイズ（100%）」で印刷すると選んだ大きさで、「用紙に合わせる」で A4 などに合わせて出ます。
   - 用紙を選ばないときは A4 に収まります。
   - 30ページを超えると、30ページごとに別の PDF に分けて作ります（iPad のメモリを使いすぎないため）。

## 児童生徒ごとの切り替え

上の「つかうひと」を切り替えると、その人の登録文字・ことば・作品に加えて、入力方法やガイド、仕上げのフォント・向き・文字数などの設定もまとめて切り替わります。

## バックアップの読み込み

- 「コードを つくる」は、ふつうは**いま選んでいる1人分**です。「ぜんいんぶんを 1つの コードに する」にチェックを入れると全員分になります。学校の保存場所に残すときは全員分がおすすめです。
- コードには、登録文字・ことば・文章（言葉の選び直しの情報、区切り、「はじめに・つぎに・さいごに」の状態を含む）・下書き・作品・写真・設定（児童生徒に見せるものを含む）が入ります。
- 同じ人のデータがすでにあるときは「べつの ひととして ついか」「いまの データを おきかえる」を選べます。置き換えたあとでも「おきかえる まえに もどす」で1回分だけ元に戻せます。
- 読み込むデータはアプリが中身を確かめ、おかしな値は初期値に直します。iPadの保存場所が足りないときは読み込まず、今のデータをそのまま残します。
- 前に保存したデータが壊れているとき（読めない・中身がおかしい）は、元のデータを消さずに別の場所へ何回分でも取っておきます。「せってい」に、取り出すボタンと、直したことの一覧が出ます。取っておけないときは、元のデータを上書きしないよう保存を止めます。
- 読み込めるコードの上限は 33,554,432文字（約3355万文字）、ファイルは 96MiB です。iPad に保存できる量より大きくしていますが、書き出したコードが必ず元どおりに読み込めるとまでは確かめていません（確認が必要な点）。
- 1つの文字の線は200本まで、題は60文字まで、名前は30文字まで、言葉は30文字・1つの欄に500こまで、文は1000こ・1つの文は1995文字まで（「さいごに、」などの順序の言葉を付けても2000文字に収まる長さ）です。これより多くは、入力するときに止めて知らせます。「じゆうに かく」の欄は長くても消さずに残し、「あと ○もじ へらしてね」と知らせます。前のデータの長い文に順序の言葉が付いて上限を超える場合は、文を入れる・並べかえる・消すなどの操作を断って知らせます（文章は変えません）。
- 保存してあったデータや読み込むコードが上限を超えていたときは、だまって減らしません。減らしたことを知らせ、保存してあった元のデータは別の場所に残します。

## 保存した作品について

- 作品には、保存したときの登録文字と名前が一緒に入ります。あとで文字を書き直したり名前を変えたりしても、作品一覧・ひらく・PDF・まとめPDFは保存したときのままです。保存したときにまだ登録していなかった文字は、あとで登録しても薄い字のままです（作品の見た目を変えないため）。
- 登録文字の情報を持っていない古い作品（2026-10-30 の更新より前に保存したもの）は、今の登録文字で表示します。
- 原稿用紙に直接書いていた、さらに古い形の手書き作品は、一覧とまとめPDFではそのまま見られますが、「ひらく」ことはできません（今の1文字ずつの手書きに移せないため。作品は消えません）。
- 作品を開いて文章を変えると、新しい作品として、今の文字と名前を使います。
- 作品を開くと、それまでの文章・手書き・区切り・作りかけの文は「したがき」に移ります（文章・手書き・作りかけの文のどれもないときは移しません。したがきは1つだけで、新しく移すと前のしたがきと入れかわります）。作品には前の区切りと文の作り方が入っていないので引き継ぎません。区切りは②で設定し直せます。
- PDF を分けて作ったときは、ダウンロードの名前の最後にも番号（_1・_2）が付きます。
- 「iPadの もじ」（フォント）で仕上げた作品は、文字の形を保存しているわけではありません。使うiPadのフォントによって見た目が変わることがあります。見た目をそのまま残したいときは、PDFも一緒に保存してください。

## バックアップ（JSON）と PDF の役割

| | バックアップのコード（JSON） | PDF・画像 |
|---|---|---|
| 中身 | 登録文字・言葉・文章・作品・写真・設定 | 仕上がった見た目だけ |
| あとで直せるか | 直せる（読み込めば元どおり） | 直せない |
| 使いみち | iPadの引っ越し・データを失ったときの復旧 | 印刷・掲示・記録 |

- バックアップのコードは、ふつうは今選んでいる1人分です。全員分は「ぜんいんぶんを 1つの コードに する」にチェックを入れて作ります。
- 写真・名前・困りごとが入ることがあるので、**学校が認めた場所**に保存してください。
- おすすめの時期：最初に文字を登録したあと、大事な作品ができたあと、学期や単元の区切り。

## 注意

- Safari の「履歴とWebサイトデータを消去」をするとデータが消えます。定期的に「せってい → バックアップ」でコードを作り、保存しておいてください。

## 開発するとき（プログラムを直す人むけ）

アプリは `index.html` 1つで動きますが、直しやすいように中身を `src/` に分けています。**直すのは `src/` で、`index.html` は組み立てて作ります。**

| 場所 | 中身 |
|---|---|
| `src/head.html` | ページの頭（タイトル・フォントの読み込み） |
| `src/body.html` | 画面の部品と見た目（HTML と CSS） |
| `src/js/01-store.js` | 共通の道具、保存（localStorage） |
| `src/js/02-screen.js` | 画面の切り替え、先生／児童生徒モード、読み上げ |
| `src/js/03-make.js` | ① ぶんをつくる（型・ことば・並べかえ・写真） |
| `src/js/04-typing.js` | ② うってみる（ローマ字・かな入力、区切り） |
| `src/js/05-draw.js` | 線をえがく共通処理 |
| `src/js/06-finish.js` | ③ しあげる（体裁・ページ・手書き） |
| `src/js/07-export.js` | PDF・画像づくりと送信 |
| `src/js/08-glyph.js` | もじとうろく |
| `src/js/09-setting.js` | せってい、バックアップ |
| `src/js/10-start.js` | 起動 |

ファイルは番号の順につながって1つのプログラムになります（順番を変えると動かなくなることがあります）。

### 組み立てとテスト

[Node.js](https://nodejs.org/) が必要です。

```sh
npm ci               # 最初の1回だけ（テスト用のブラウザ部品 Playwright を入れる。版は package-lock.json で固定）
npx playwright install chromium   # 最初の1回だけ
npm run build        # src/ から index.html を作る
npm test             # 全部のテスト（iPad 6画面の通しテストを含む・数分かかる）
npm run test:quick   # 通しテストをとばした速いテスト
```

- `tests/features.test.js`：機能ごとのテスト（文末の変化、並べかえ、写真など）
- `tests/stage1.test.js`：保存と復元、作品の見た目固定、表示設定、文の扱い、入力と学習、iPad操作、まとめPDFのテスト
- `tests/p1.test.js`〜`tests/p6.test.js`・`tests/p7.test.js`（漢字を打てない）・`tests/p8.test.js`（カタカナ・キーボードの並び・数字）・`tests/p9.test.js`（第11回：手書きを守る・作品の文字・分かれた濁点・古い漢字）・`tests/p10.test.js`（第12回：取り消し・2つで1文字の漢字・くとうてん）・`tests/p11.test.js`（第13回：離れて戻る・30こ超の取り消し）：チャッピーの再評価ごとの確認（第5回・第6回は、動きを減らす設定・選んでいる印・色の比・印刷・断ったときに何も変えないこと など）
- `tests/e2e.test.js`：iPad の6つの画面サイズで①〜③を通しで操作し、はみ出しやエラーがないか確かめる。画面の写真と PDF は `tests/out/` にできます。
- テストは小さなサーバー（`http://127.0.0.1`）で配信して行います。`BROWSER=webkit npm test` で Safari と同じエンジン（WebKit）でも試せます（先に `npx playwright install webkit`）。
- GitHub に送ると、`.github/workflows/test.yml` が Chromium と WebKit で自動テストします。結果はリポジトリの「Actions」タブで見られます。
- ただし、これらは iPad 実機の Safari・Apple Pencil・共有画面の確認の代わりにはなりません。
- テストは最初に「`index.html` が `src/` と同じか」を確かめます。`src/` を直したら `npm run build` を忘れずに。
- アプリを更新したら、`src/body.html` の「更新日」を書きかえてください。
